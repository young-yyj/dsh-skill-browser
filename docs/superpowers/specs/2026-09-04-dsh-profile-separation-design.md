# DSH 稳定版与开发版 Profile 分离设计

## 目标

将插件的稳定运行环境与源码开发目录解耦：删除、移动或重新克隆本仓库后，日常使用的 DSH `web` profile 不受影响；同时保留源码改动后可立即验证的开发环境。

## 方案

| 环境 | Profile | 插件来源 | 适用场景 |
| --- | --- | --- | --- |
| 稳定版 | `web` | DSH Home 中的版本化 `.tgz` 本地包 | 日常使用 |
| 开发版 | `web-dev` | 指向当前源码目录的 `link:` 依赖 | 功能开发和即时验证 |

稳定版包存放在 DSH Home 的本地归档目录。该目录由运行时 DSH Home 解析得到，不能写死任何用户名或项目目录。每个版本保留独立的 `.tgz` 文件，便于回退。

## 开发数据流

1. 在仓库修改 TypeScript/React 源码。
2. 运行 `npm run verify`，覆盖类型检查、测试与构建。
3. `web-dev` 通过链接读取构建后的 `lib/`，重启其 DSH Web 实例后即可验证。
4. 确认后提高版本号、重新构建并运行 `npm pack`。
5. 将生成的 `.tgz` 复制到 DSH Home 的稳定归档目录。
6. 通过 DSH 插件管理命令将 `web` 更新到该归档包，并重启稳定 DSH Web。

## 安全与回退

- 绝不降低或绕过 `minimumReleaseAge`、完整性校验或锁文件校验。
- `.tgz`、DSH profile、DSH Home 配置与任何密钥均不提交到仓库。
- 切换稳定版前保留上一版本 `.tgz`；如果新版本验证失败，恢复到上一版本包。
- 只有已选会话时，插件入口才会出现在 DSH Web 的会话标题栏；空会话首页不作为界面入口验证依据。

## 验收标准

- 删除或移动源码目录后，`web` profile 仍能启动并加载稳定插件。
- 在 `web-dev` 修改源码、运行构建并重启后，可看到新行为，无需重新安装开发插件。
- 稳定版升级不依赖源码目录，且可保留上一版本包用于恢复。
- 迁移过程未修改或绕过 DSH 供应链安全策略。
